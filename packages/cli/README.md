# 需求背景

企业级软件开发面临的三大问题：

-   规范化（代码风格、目录结构、命名不一致）
-   流程化（多模块流程复杂、人工易出错）
-   自动化（重复劳动耗时易错）

解决思路是把这些 工程化约束 标准化 后封装进命令行工具，让开发者一条命令即可完成项目搭建，无需了解底层工程细节。

# 基本使用

```bash
npm install -g @nz-cli/cli
# 安装成功后，查看使用帮助
ning --help
```

# 业务分析

① 规范化（统一代码风格、目录、构建、测试等标准）

-   ESLint + Prettier + husky：统一代码风格、命名规范，提交前自动检查，防止个人习惯差异
-   目录结构约定：脚手架预设 src/components、src/views 等标准目录，团队成员新建项目结构一致
-   commitlint：规范 Git 提交信息格式（如 feat: xxx），便于追溯

② 流程化（初始化、配置、测试、部署等环节的固定流程）

-   npm scripts 统一入口：npm run dev / build / test，把散乱的命令收敛成固定流程
-   CI/CD 流水线：代码提交后自动走 "安装依赖 → 跑测试 → 构建 → 部署" 的标准流程，减少人工漏操作
-   多环境配置管理：.env.development / .env.production 统一环境变量切换流程

③ 自动化（替代重复劳动，保证一致性）

-   脚手架一键初始化：如 npm create vue 一条命令生成完整项目，无需手动配 Webpack/Vite
-   自动化测试：单元测试 + CI 中自动执行，提交代码即自动回归
-   自动部署 / 发版：如 GitHub Actions 监听 push 自动构建发布，无需人工重复操作

简单说：规范化管 "标准统一"、流程化管 "步骤固定"、自动化管 "机器代劳"。
